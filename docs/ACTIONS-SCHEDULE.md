# ⏰ 定时策略与飞书静默时段

## 为什么提前 30 分钟起跑

GitHub Actions 的 `schedule` 触发不保证准点：实测延迟从几分钟到数小时不等，偶发整段丢时段。
因此本仓库所有 cron 都在**目标时段前 30 分钟起跑**，用提前量对冲常规延迟——目标时段不变，白天延迟了也只是晚点跑。

## 飞书静默时段：23:00–07:00（北京时间）

延迟特别大时，任务可能被拖进深夜。为保证不被打扰：

- **北京时间 23:00–07:00** 完成的任务**不推送飞书**，只在 Actions 运行日志里记录结果；
- 白天完成的任务照常推送；
- 「飞书推送测试」workflow 是手动测试入口，**不受静默时段限制**。

## 已知限制

- 极端延迟（1 小时以上）仍会把任务本身推晚——提前量只能对冲常规延迟，静默时段保证的是"深夜不弹消息"；
- 静默时段被跳过的推送不会补发，结果以 Actions 日志为准。
